# v9：配置读取诊断、大请求准入和本地开发误命中

基线为 `47ab8bfbf70b66b9d0dd14d2b9c4c16fba16c85a` / v8。事故 SQL 显示默认审计配置存在且启用，路由绑定为 NULL；按 Store 的既有逻辑，这会选择默认配置，不需要把 NULL 强制改成 ID=1。查询只能说明当前状态，不能回推事故发生时数据库没有瞬时故障。

## 发现与限定

- v8 把配置不存在、禁用、数据库读取失败和超时合并为 `audit_profile_unavailable`。零模型调用时不能归因于千问幻觉或其 8000 ms 推理超时。
- 多 MiB 文本可能耗尽前处理时间，并且远超 16 KiB 分块、双审计和有限调用预算的实际容量。64 MiB 是请求接收上限，不是完成模型审计的能力承诺。
- 内置凭据规则把用户在终端隐藏输入 Token 当成秘密提取；认证设计讨论被模型当成绕过；默认系统提示提取正则跨防护表格的两行组成了一个不存在的动作。这些是命中依据错误，不能据此保证完整未展示请求安全。
- CSV 中的输入图片覆盖错误与并发 503 是独立问题；本次没有伪造图片审计完成，也没有扩大并发或关闭资源保护。

## 实现

1. 新增 `audit_preflight`：记录 input_extract/capacity/rules/profile_lookup/source_scope/model 分阶段耗时、默认或指定配置选择、选中 ID 和失败阶段。超时、取消、配置缺失、禁用、存储错误分别记录；不输出 DSN、数据库原始错误消息、端点、正文或密钥。
2. 配置读取最多 5 秒并继承总请求截止时间；过期上下文不能从缓存获得“可用配置”。路由不绑定时依旧使用默认配置，没有数据库迁移或自动更改启用状态。
3. 完整提取后、重型规则扫描前计算实际分块数。必需的双审计无法在最大分块/256 HTTP/128 复核预算内完成时，以 `input_too_large` 故障拒绝，不调用模型、不丢弃历史，也不标成攻击。总截止时间、模型分块、并发和既有 555 契约不变。额外 Fusion/恢复可能仍耗尽共享预算，仍拒绝。
4. JSON 读取支持上下文取消，收集阶段和各前处理阶段检查取消；大型正则扫描用可取消 RuneReader，取消后的部分扫描结果绝不视为有效。无后台扫描 goroutine。无赋值分隔符的普通文本跳过不可能命中的秘密赋值正则；匹配语义不变。
5. 仅对内置凭据规则中完整行明确为终端隐藏输入的命中，以及精确匹配默认表达式的跨防护表行误拼接，取消该条错误命中并继续检查后续匹配和其他规则。全部文本继续进入模型，未增加本地/localhost/SSH/Token 全请求白名单。自定义表达式不变；同一请求的真实秘密提取、绕过、扫描仍阻断。
6. 认证请求头方案与主动输入凭据的弱模型证据，进入既有一次操作校核，原文/任务锚点不变。反复弱证据或校核错误仍按审计故障返回 555。正常设计不代表安全设计：真实密钥不宜进入提示词，服务端仍需校验签名、主体和权限，不能仅信任客户端声明。此修正不授权伪造凭据或权限绕过。

## 验证边界

先用脱敏样例在 v8 复现四项失败，再修实现。保留真实规则否决、双审计、Fusion、输入覆盖、长历史及无效证据恢复测试。新增测试涵盖默认 NULL 绑定、超时/取消/缺失/禁用/存储错误区分、诊断隐私、超大请求提前拒绝、可取消正则、终端输入、认证方案、表格跨行、后续真实命中、管理员自定义规则和重复弱证据失败。

新增 12 项可销毁 Mock 栈 HTTP/SSE 用例集成既有完整 E2E。测试是机制验证，不是真实 Qwen3.8-27B 准确率测量。未连接用户数据库、SSH、服务或生产模型。不能保证所有“本地开发”或原始超长请求最终放行。先前无标签密码脱敏、通用语义误报、图片支持不属于本次完成项。

Go 取消传播依据：https://go.dev/doc/database/cancel-operations 。这是诊断机制依据，不证明事故原始错误必然是超时。

## 部署与检查

使用既有升级入口，不修改数据库绑定，不清空数据卷：

```bash
cd /opt/newapi-risk-platform
RESET_DATA=0 BACKUP_DATABASE=1 ALLOW_BRANCH_SWITCH=1 bash scripts/upgrade.sh main
```

外置数据库需要独立备份。检查新请求 `gateway_build.audit_engine=cyber-deny-qwen27b.v9` 及实际提交；`audit_preflight.profile_selection=default`、`selected_profile_id=1` 可以证实正常默认选择。失败时先看 failure_stage 和 error_class；旧历史不会重写，审核附表也不是在修改生产事件。
